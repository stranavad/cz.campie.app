# Web

The marketing website on the bare domain `campie.cz`: five pages (`/`, `/co-umi`, `/bezpecnost`, `/kontakt`, `/weby-pro-tabory`) and the starter kit for camp organisers (below), built as static HTML by Astro, plus one small Cloudflare Worker that answers the contact form at `/api/kontakt` and the website-proposals form of `/weby-pro-tabory` at `/api/weby` (`worker/weby.ts`: same Turnstile, rate limit binding under its own key and Resend mail; its fields in `worker/weby.fields.ts`, shared with the page's script; result pages under `/weby-pro-tabory/`). It is outside the platform: no Organisation data, no session, no call to `apps/api`. Signup, login and the legal pages are the platform's (`app.campie.cz`), linked, never copied.

## Scripts

In `apps/web`, or from the root `pnpm --filter web <script>`.

| Script                   | Purpose                                                                           |
| ------------------------ | --------------------------------------------------------------------------------- |
| `pnpm dev`               | Astro dev server on `http://localhost:4321` (no Worker: the form cannot send)     |
| `pnpm build`             | static build into `dist/`, then a dry run of the Worker bundle                    |
| `pnpm preview`           | `wrangler dev`: the last build and the Worker together, as Cloudflare serves them |
| `pnpm check-types`       | TypeScript                                                                        |
| `pnpm lint`              | Oxlint, type-aware, warnings fail                                                 |
| `pnpm test`              | Vitest: the Worker, the pure modules and assertions over `dist/` (build first)    |
| `pnpm deploy:production` | builds with `SITE_ENV=production` and deploys `campie.cz`                         |
| `pnpm deploy:dev`        | builds with `SITE_ENV=dev` and deploys the preview on `dev.campie.cz`             |

`SITE_ENV` decides indexing and links: `production` is indexable and links `app.campie.cz`; `dev` and unset (local) send `noindex` everywhere and link `app.dev.campie.cz`. Canonical URLs always name `https://campie.cz`. Local builds use Turnstile's test key; `pnpm preview` needs `.dev.vars` (copy `.dev.vars.example`).

## Stack

| Area    | Tech                                                                                        |
| ------- | ------------------------------------------------------------------------------------------- |
| Pages   | Astro 7, static output, no adapter; Preact only for the kit's configurator (below)          |
| Styling | Tailwind CSS 4, theme tokens in `src/styles/global.css`, dark theme from the system setting |
| Fonts   | Fontsource files, `@font-face` by hand in `src/styles/fonts.css`, latin and latin-ext only  |
| Worker  | `worker/`: plain `fetch` handler, Zod, Turnstile, Resend over HTTP, a rate limit binding    |
| Images  | Open Graph cards and icons with Satori and sharp (`src/lib/og.ts`); photos in `src/assets/` |
| Hosting | Cloudflare Workers with static assets (`wrangler.jsonc`)                                    |

## Where things live

- `src/content/*.ts`: every text and link, page by page in section order, plus `seo.ts` (titles, descriptions, Open Graph). Texts may use `**bold**`, `` `code` `` and `[text](href)`; `src/lib/inline.ts` renders them. A platform link is written `app:/path`.
- `src/components/`: templates. `home/` the home page's sections, `illustrations/` the small drawings, `screens/` the four platform screens drawn in HTML. Demo values (names, prices, dates) live in these components, not in content.
- `src/lib/`: the logic, all typed: links, JSON-LD, the Markdown twins and `llms.txt`, `_headers`, `robots.txt`, images.
- `src/pages/`: thin pages and the generated files (`robots.txt`, `llms.txt`, `llms-full.txt`, `/<page>.md`, `/og/<page>.png`, `/vzory/<slug>.pdf`, icons).
- **One site, three parts.** Every page belongs to the product (Campie), the kit (Průvodce a vzory: `/pruvodce`, `/vzory` and below) or Weby (`/weby-pro-tabory`). `src/lib/nav.ts` tells the part from the page's path (`partOfPath`) and builds what `Base.astro` wraps every page in (`pageFrame`): one `Header`, `Breadcrumbs` from the page registry on every indexed page but the home page (the same trail is the JSON-LD `BreadcrumbList`), on kit pages the `KitAbout` block ("Kdo za Průvodcem stojí") above the footer, and one `Footer`. Pages render none of these themselves; product pages close with `CtaBand` on their own. Texts in `src/content/site.ts` (`header`, `breadcrumbs`, `kitAbout`, `footer`).
- **One bar, nothing unfolds.** The header is four plain links (Co umí, Průvodce, Vzory, Weby pro tábory; the one the page's path lies under is marked), then on kit pages the search magnifier, "Přihlásit se" and the button of the part ("Vyzkoušet zdarma", the quiet "Co je Campie?", "Chci návrhy zdarma"). No bar under it: the page starts at once. The breadcrumbs are the page's first quiet line, no band of their own (over a forest `PageHero` they take its colour, a `:has()` rule in `global.css`). The phone's drawer is a `<details>` with the four links, on kit pages the search, then the two actions; `menu.ts` only closes it (link followed, Escape, click outside).
- **Every guide and template in every page's HTML** goes through the footer: its "Průvodce a vzory" column lists all guides (in the order of `hub.guides.groups`, under their `menu` name) and all templates, with `/pruvodce` and `/vzory` (`footerNav` in `nav.ts`).
- **The kit's search**: `/hledani.json` (`src/lib/search.ts`) is built from the content: the guides, each section with its Facts' text, the templates. `SearchForm` sits in the header's panel (opened by the magnifier, kit pages only) and in the phone's drawer; the magnifier and the fields are hidden without JavaScript. `search.ts` shows them, opens and closes the panel (Escape, a click outside or a followed link close it and return the focus to the magnifier), fetches the index on the first focus and filters it in the browser (every word, accents and case aside), linking the section anchors.
- The sitemap is split by part behind `sitemap-index.xml`: `sitemap-produkt-0.xml`, `sitemap-pruvodce-0.xml`, `sitemap-vzory-0.xml` (with the blank PDFs) and `sitemap-weby-0.xml` (`sitemapSection` in `nav.ts`).
- `src/content/seo.ts`: the one registry of indexed pages. Every page in it gets its canonical URL, a sitemap entry with `lastModified`, an Open Graph image, a Markdown twin and a line in `llms.txt`; the kit's pages join it from their content.
- `src/scripts/`: the only client JavaScript: closing the phone's drawer (`menu.ts`), the kit's search (`search.ts`), the hub's deadline calculator (`deadlines.ts`), sending the contact form and the two forms of `/weby-pro-tabory` (`weby-form.ts`) in place, and mounting the kit's configurator (`configurator.tsx`).
- Analytics: self-hosted Umami, cookieless, loaded only by production builds (`umami` in `src/lib/site-env.ts`). Click events are `data-umami-event` attributes from `linkEvent` in `src/lib/analytics.ts`; script events go through `trackEvent`. Events: `signup` and `login` (property `place`), `contact-sent`, `weby-sent`, `kit-download` (properties `template`, the slug, and `variant`, `blank` or `custom`; the blank PDF is a link counted by `downloadEvent`, the custom one is sent by the configurator; never a typed value).

## Starter kit

Free guides and document templates for camp organisers: the hub `/pruvodce` and one page per guide at `/pruvodce/<slug>`; the list of templates `/vzory`, one page per template at `/vzory/<slug>` and its blank PDF at `/vzory/<slug>.pdf`.

- **Writing or re-checking the legal content** follows [`docs/kit-content.md`](docs/kit-content.md), the brief for a person or a model; `pnpm kit:check` (`scripts/check-kit-sources.ts`) downloads the cited regulations and checks every cited anchor and every `quote` against them.
- **No statement without a source.** Every statement is a `Fact` with a `basis` (law, authority, practice, advice) and at least one `Cite`, and a `Cite` can only name a source of `sources.ts`. A page cannot say what it cannot link; a regulation's own words go verbatim in `quote`.
- Content: `src/content/kit/` - `types.ts` (the model), `sources.ts` (every source), `cite.ts` (`par()` and `at()`), `guides/` (one file per guide, the order in `guides/index.ts`), `hub.ts` (the hub's texts and `kitLabels`, every word the kit's templates use), `document-list.ts` (the templates as the guides link them), `documents/` (the document model `types.ts`, one file per template, `index.ts` with the order, `/vzory`'s texts and `documentLabels`, every word of the document pages, the configurator and the printed documents).
- Logic: `src/lib/kit/` - `facts.ts` (a Fact as shown, citation links, the sources a page cites), `links.ts` (hrefs and cards), `pages.ts` (what each template renders, and the hub's list of changes, derived from the Facts that carry a `change` sentence, with `since` on or after `hub.changes.from`). Templates: `src/components/kit/`, `src/pages/pruvodce.astro`, `src/pages/pruvodce/[slug].astro`, `src/pages/vzory.astro`, `src/pages/vzory/[slug].astro`.
- **The claim row** (`Fact.astro`, the design's "tvrzení") is how every page of the kit shows a Fact: the basis mark (`BasisBadge`: § Zákon, Ú Výklad úřadu, O Doporučení organizace, c Naše doporučení, told apart by the mark's border and shape, not by colour alone), the statement with the regulation's words in a `details` and its tags (`Tag`: "I menší akce", "Novinka 2027" for a Fact in force from `kitLabels.newFrom`, otherwise "Platí od"), then the citations in mono (`CiteLinks`, "vychází z" before our own advice's). Three columns from 640px of the row's own width (a container query), one below. `Claims` lists rows with hairlines and marks each `data-rule` (`data-small` when it also binds a smaller event); `Legend` is one line of the four marks opening to what they mean; `Verification` is the line of season, "Ověřeno" and the legal state. Cards: `GuideCard` (`guideCardView`, from `hub.guides.groups`), `TemplateCard` (`templateCardView`), `SheetDrawing`.
- **The guide page**: verification line, `h1`, lead and the counts; `ContentsList` (sticky beside the text from `lg`, a `details` on phones); the sections as numbered `h2` (each an anchor) over `Claims`; templates and related guides as cards in the text column; sources, disclaimer, previous and next guide in the order of `hub.guides.groups`. "Jen pravidla pro menší akce" is a checkbox and a `:has()` rule at the end of `global.css` (`[data-kit-filter]`): it hides rows, sections and contents entries without `data-small`, which stay in the HTML. Breadcrumbs and the closing block come from `Base.astro`.
- **The hub** `/pruvodce` (`hubPage` in `pages.ts`, sections in `src/components/kit/hub/`): the hero right under the breadcrumbs (the year's news as a chip linking `#novinky`, `h1`, lead, the verification line without the season, three entry cards to `#akce`, `#kdy` and `#vzory`), `#akce` (the two kinds of event from `hub.decision`, rule counts computed from the Facts), `#kdy` (the timeline of `hub.timeline.steps`, each Fact as a compact `ClaimCard`), `#pruvodci` (the groups' cards without their one line: `GuideCard` takes `summary={false}`), `#vzory`, `#novinky` (from `kitChanges()`). The timeline is complete in the HTML; the date field is hidden until `src/scripts/deadlines.ts` shows it and writes each step's day (from `offset`) and distance and the summary line (a step's `summary`). The date math is `src/lib/kit/deadlines.ts`; the script imports no content, its words come in `data-labels`. The chosen day is kept in `localStorage`, none is preset.
- **The template page** (`/vzory/<slug>`, `documentPage` in `pages.ts`): verification line, `h1`, lead, the one rule the hero answers with (`explain.answer` of the template, a Fact of a guide section or of its own) and the two ways to the document (the blank PDF with its pages and size; "Upravit na svůj tábor", hidden without JavaScript; for the form, why it cannot be changed instead); the configurator beside the A4 preview (two columns from `xl`, the preview sticky, only while the configurator is shown); then on a card-coloured band what the law says (`Claims`), "Co který bod dělá", the disclaimer, and beside them the related guides and templates as small cards and the sources. No CtaBand: "A příští rok bez papírů?" with the template's `inCampie` shows only after a download.
- **One model, three outputs.** `document.ts` turns a template, the organiser's `KitSettings` and their `TemplateChoices` into one `PrintDocument` (letterhead, title, a flat list of printable blocks, footer), and cuts the blocks into units (`printUnits`: a block, or a heading with the block under it), which never split across pages. `pdf.ts` renders it to a pdfmake definition, `preview.ts` to HTML strings, and the configurator edits the inputs. No renderer reads a template itself. A blank document is the preset: default items, no letterhead; a `kind: 'form'` template prints as it stands, without letterhead, configurator or credit line.
- **One page if it fits.** `sheet.ts` holds the A4 page, its margins and a ladder of four densities (10.5 pt body down to a 9 pt floor; a fill-in line never under 15 pt). A document is set at the roomiest density at which it is one page; a template that never fits takes the roomiest and runs on, the form the roomiest with the fewest pages, so its break falls between whole boxes. The form is set tighter at every step (`FORM` in `sheet.ts`: smaller gaps between fields and parts, framed parts with less padding) and uses the layout the model allows it: a field with `inline` has its short label on its line's left, options stand in one row, a part holding only one unlabeled line writes its title on it (`titleOnLine`), and a half-width field beside a full-width one takes a third of the row. So the posudek fits one page at 9.5 pt, with the Poučení and the Poznámka in small print (8 pt). The PDF finds its page count from pdfmake itself (`fitPdf`: each unit carries an id that `pageBreakBefore` reports, the footer counts the pages).
- **The preview is the PDF's pages, scaled.** Each preview page is an A4 sheet (`aspect-ratio` 210:297, growing rather than clipping) whose measures are points of the page width (`--pt`), from the same constants as the PDF; the stylesheet is written by `sheetCss()` and set in the page's head. The static preview takes its pages and density from the blank PDF's own pdfmake layout at build time (`documentPreview` in `pages.ts`, `blankPdf` in `pdf-node.ts`), so nothing shifts on load. The configurator paginates live without pdfmake (`measure.ts`): it sets the document in an unseen 794 px page at each density, measures the units and fills pages greedily, with a 1.5% margin of safety so the preview runs on before the PDF would. Below 640 px of page width the sheets keep their pages but reflow at a readable fixed size (1 pt = 1.4 px) instead of scaling down.
- **PDFs without a server**, with pdfmake and Figtree's static TTFs (`@expo-google-fonts/figtree`, full Czech coverage). The same definition is written by `pdf-node.ts` at build time (`src/pages/vzory/[slug].pdf.ts`, fonts read from disk) and by `pdf-browser.ts` in the browser, which the configurator imports dynamically on "Stáhnout PDF", so pdfmake (about 290 kB gzip) and the fonts are never part of a page; the fonts are fetched from this site. pdfmake decodes a PNG in a Web Worker made from a blob URL, which the Content-Security-Policy blocks, so the configurator keeps the logo as a JPEG.
- **The configurator** (`src/components/kit/ConfiguratorForm.tsx`) is the one exception to "no client framework": a form with lists that grow and shrink, in Preact. It is mounted by hand by `src/scripts/configurator.tsx` into the hidden place `Configurator.astro` renders, never as an Astro island or with `@astrojs/preact`, whose hydration runs inline scripts the Content-Security-Policy forbids. Only customisable template pages load it; without JavaScript the place stays hidden and the page keeps the preset preview and the blank PDF. Settings live in `localStorage` under one versioned key (`settings.ts`, a `zod/mini` schema; what does not parse is dropped): the organiser and the camp shared by all templates, the choices per template. Nothing typed leaves the browser.
- The form is three numbered cards (organiser and camp, the items as switches in "V dokumentu" and "Můžete přidat" with their why and an inline editor, the credit line) over a forest download bar sticky at the bottom. Its states: "Vítejte zpět" when stored data were found (keep or clear them), the logo error naming the file, "Připravuji PDF" (button disabled, spinner, what is loading), the PDF error with "Zkusit znovu" and the blank PDF, and after a download the file name and the bridge to Campie. The preview's line (`[data-preview-bar]`: pages, and the note when the document runs to more than one page) and the phone's sticky switch "Upravit / Náhled" (`[data-cfg-tabs]`, below `xl`, with a "Náhled" button above the download bar) stand outside the form in the page's HTML; the form renders into them with `render` and sets `data-tab` on the section (`[data-cfg]`), whose `group-data-[tab]` classes show the form or the preview. No `style=` anywhere, Preact included.
- The site's modules read `SITE_ENV` through `process.env`; `astro.config.ts` defines it for the browser bundle, since the configurator imports some of them.
- Printing a document page prints its A4 pages alone, one per sheet at real size (`data-print-sheet`, the print rules at the end of `global.css` and in `sheetCss()`). The sheet is paper in both themes: the `--sheet*` colours do not change with the theme.
- The template pages are wider than the rest of the site: `Base.astro` takes `wide`, which sets `--wrap-max: 1340px` for the header, the content and the footer alike; every other page keeps 1200px.
- A guide's or a template's `verified` date is its `lastModified` in the sitemap and its `Article` date in JSON-LD; set it when it is checked against its sources again. The blank PDFs are in the sitemap with their template's date.

## What we deliberately do not do

- **No logic in `.astro` files.** `astro check` needs TypeScript 5 or 6 (ADR-0003 uses 7), so `.astro` frontmatter is not type checked. Templates import content and map over it; anything that computes lives in a `.ts` module.
- **No inline scripts and no `style=` attributes.** The Content-Security-Policy allows only this site's script files, the speculation rules, Turnstile and, in production, Umami. JSON-LD is a data block.
- **No client framework, no third party** except Turnstile on `/kontakt` and `/weby-pro-tabory` and the self-hosted Umami; Preact on the kit's customisable template pages is the one exception (above). No analytics that set cookies or need consent.
- **No raw colours in components.** Only the tokens of `global.css`, which carry both themes.
- **No text outside `src/content/`**, apart from demo values in illustrations. Hyphen "-", never an em-dash.
- **No screenshots of the platform.** The screens are HTML, so they follow the theme and stay sharp.

## Cloudflare setup (manual, once)

Nothing here is automated; the repository holds no Cloudflare credentials.

1. DNS: the `campie.cz` zone on Cloudflare. The Worker's custom domains (`campie.cz`, `dev.campie.cz`) create their records on the first deploy. A Redirect Rule sends `www.campie.cz` to `https://campie.cz`. The platform's records (`app`, `*`, `app.dev`, `*.dev`) keep pointing at the server.
2. Workers Builds (or a manual `pnpm deploy:*`): two projects, `campie-web` on branch `main` with deploy command `pnpm run deploy:production` and `campie-web-dev` on branch `dev` with `pnpm run deploy:dev`, build command `pnpm install --frozen-lockfile --filter web...` (the deploy scripts build with the right `SITE_ENV`; Cloudflare's default `wrangler deploy` would ship a noindex build). Root directory `apps/web`, build variables `NODE_VERSION` (26) and `PNPM_VERSION` (from `packageManager`), watch paths `apps/web/*` and `pnpm-lock.yaml`, non-production branch builds off.
3. Turnstile: a widget for `campie.cz` and `dev.campie.cz`; its site key replaces the placeholder in `src/content/site.ts`, its secret goes in with `wrangler secret put TURNSTILE_SECRET_KEY` (and `--env dev`).
4. Resend: a sending key for `posta.campie.cz`, set with `wrangler secret put RESEND_API_KEY` per environment.
5. Zone settings off: Block AI bots, Managed robots.txt, Rocket Loader, Email Address Obfuscation (each rewrites what this site serves).
6. After the first production deploy: submit `https://campie.cz/sitemap-index.xml` to Google Search Console, Bing Webmaster Tools and Seznam Webmaster.
