## Findings considered and rejected

- Per-Organisation rate limits locking families out at a registration opening: the submission limit counts against the Organisation only after the answers validate, and the example limits (5000 per hour) are far above a real opening.
- Comgate calls inside a database transaction: bounded by a 5 s timeout, a pool of 25 and per-address limits.
- In-memory filtering and no pagination in the participant list: documented as deliberate, since encrypted columns are never filtered in the database and a Turnus holds a few hundred children.
- Inline file downloads on the app's origin: content types are decided from content (PDF, JPG, PNG, WebP) and served with `nosniff`.
- Gotenberg render without a timeout: runs in a job, bounded by the HTTP client's default timeouts; low value.
- One-click removal of a Discount code: only a code nobody used can be removed, and recreating it takes seconds.
